De la web al APK: cómo se arma una app híbrida

Ya conocen JavaScript, TypeScript y Angular básico. Lo que cambia acá no es el lenguaje — es que el código termina corriendo dentro de un teléfono Android real, con cámara, GPS y notificaciones incluidos. Esta guía cubre qué instalar, cómo se reparten el trabajo Angular, Ionic y Capacitor, y para qué sirve Android Studio en todo esto.

Angular Ionic Capacitor Android Studio
01

Qué instalar en el entorno de desarrollo

El orden importa: cada herramienta depende de la anterior. Esto es para Windows, que es lo que usa el equipo; en Mac/Linux los pasos son casi iguales, solo cambia cómo se configuran las variables de entorno.

1

Node.js (versión LTS)

Es el motor que ejecuta JavaScript fuera del navegador. Angular CLI, Ionic CLI y todos los paquetes de npm corren sobre Node. Sin esto no se puede instalar nada más.

# verificar instalación
node -v
npm -v
2

Git

Ya lo usan para el repositorio del grupo en GitHub. Nada nuevo acá, solo confirmá que esté instalado y configurado con tu usuario/mail.

3

Angular CLI

La herramienta de línea de comandos que ya conocen (ng generate, ng serve). Ionic la usa por debajo cuando el proyecto es Angular.

npm install -g @angular/cli
4

Ionic CLI

Crea el proyecto, agrega Capacitor, sirve la app en el navegador para probar rápido, y sincroniza con los proyectos nativos.

npm install -g @ionic/cli
ionic start restaurant-app tabs --type=angular
5

JDK 17 (Java Development Kit)

Rareza aparente, pero necesaria: el sistema de compilación de Android (Gradle) corre sobre la JVM. No van a escribir una línea de Java, pero Gradle lo necesita instalado para compilar el proyecto nativo.

Opción rápida en Windows (con winget):

# Eclipse Temurin es la distribución gratuita más usada de OpenJDK
winget install EclipseAdoptium.Temurin.17.JDK

Opción manual: bajar el instalador .msi (Windows x64) desde adoptium.net/temurin/releases/?version=17, ejecutarlo y, si el asistente lo ofrece, tildar "Set JAVA_HOME variable" para que configure la variable de entorno automáticamente.

# abrir una terminal NUEVA y verificar
java -version
javac -version

Debería mostrar algo como openjdk version "17...". Si JAVA_HOME no quedó configurado solo, se hace a mano en el paso 7.

6

Android Studio

Instala de una todo el combo nativo: el Android SDK (las APIs de Android contra las que se compila), Platform Tools (incluye adb, para hablar con el celular por USB), Gradle y el emulador (AVD Manager). Es un requisito, no una opción: sin esto no hay forma de generar un APK.

  1. Descargar el instalador desde developer.android.com/studio ("Download Android Studio").
  2. Ejecutarlo y elegir la instalación "Standard" en el asistente — instala el SDK, el emulador y una imagen de sistema por defecto sin tener que elegir nada a mano.
  3. Al terminar, abrir More Actions → SDK Manager y confirmar que haya al menos una versión reciente de Android marcada (ej. Android 14, API 34) junto con Android SDK Build-Tools.
  4. Crear un emulador en More Actions → Virtual Device Manager → Create Device: elegir un dispositivo (ej. Pixel 6), descargar una imagen de sistema y finalizar.
  5. Anotar la ruta del SDK en Settings → Languages & Frameworks → Android SDK ("Android SDK Location") — es la que va a ANDROID_HOME en el próximo paso.

Android Studio trae su propio JDK embebido para uso interno del IDE, pero igual instalen el JDK 17 del paso 5: la terminal (Capacitor CLI, Gradle desde consola) lo busca por fuera del IDE.

7

Variables de entorno

Windows necesita saber dónde quedaron instalados el JDK y el SDK de Android. Se configuran en Variables de entorno del sistema:

JAVA_HOME = C:\Program Files\Java\jdk-17
ANDROID_HOME = C:\Users\<usuario>\AppData\Local\Android\Sdk

# agregar al PATH:
%ANDROID_HOME%\platform-tools
%ANDROID_HOME%\tools

Si npx cap sync android o Android Studio no encuentran el SDK, casi siempre es esto.

8

VS Code (el que ya usan)

Sigue siendo el editor principal para el 90% del código. Sumen las extensiones Angular Language Service e Ionic para autocompletado de componentes ion-*.

9

Un celular Android con Depuración USB

Activá Opciones de desarrollador (tocando 7 veces el número de compilación) y dentro Depuración USB. Para este TFI, cada uno de los 4 integrantes va a necesitar probar en su propio dispositivo, así que hagan esto desde ya en los cuatro celulares.

Tip para el TFI

El trabajo prohíbe explícitamente el modo oscuro. Ionic trae, por defecto, un bloque en variables.scss que activa colores oscuros automáticamente según el sistema del usuario (@media (prefers-color-scheme: dark)). Bórrenlo o coméntenlo apenas generen el proyecto — si no, alguien va a probar la app de noche con el celular en modo oscuro y la pantalla va a salir "incorrecta" justo en la demo.

02

Inicializar el proyecto con todo lo necesario

Esto se hace una sola vez — lo puede correr el líder — y después cada uno clona el repo. El objetivo: terminar con Angular + Ionic + Capacitor funcionando, la plataforma Android agregada, las librerías nativas que este TFI va a necesitar sí o sí, y el repo conectado a GitHub.

1. Crear el proyecto

# "tabs" es una plantilla de Ionic con navegación por pestañas ya armada
# --type=angular le dice que use Angular (no React/Vue) por debajo
ionic start restaurant-app tabs --type=angular

cd restaurant-app

El asistente pregunta si querés integrar Capacitor: decile que sí. También corre git init y hace el primer commit solo (a menos que uses --no-git).

2. Agregar la plataforma Android

npx cap add android

Crea la carpeta /android — el proyecto nativo real que después se abre desde Android Studio.

3. Backend

npm install @supabase/supabase-js

4. Plugins nativos que este TFI va a necesitar

Se instalan como paquetes npm normales: cada uno trae su parte TypeScript (lo que llamás desde Angular) y su parte nativa Android, que Capacitor conecta solo al sincronizar.

# cámara (fotos de empleados, platos, bebidas, mesas)
npm install @capacitor/camera

# ubicación (mapas para delivery, tercera entrega)
npm install @capacitor/geolocation

# notificaciones push (todo el flujo de mesas y pedidos)
npm install @capacitor/push-notifications

# vibración — excluyente: vibrar en TODOS los errores
npm install @capacitor/haptics

# acelerómetro y giroscopio (punto 31: navegar el menú por movimiento)
npm install @capacitor/motion

# guardar sesión/preferencias del usuario en el dispositivo
npm install @capacitor/preferences

# generar y compartir archivos (las facturas en PDF)
npm install @capacitor/filesystem @capacitor/share
Leer un QR vs. generar un QR — no es lo mismo

Leer un QR necesita la cámara → es hardware → hace falta un plugin nativo de Capacitor:

npm install @capacitor-mlkit/barcode-scanning

Generar un QR es dibujar una imagen a partir de un texto → es matemática pura → alcanza con una librería de JavaScript, sin nada nativo:

npm install qrcode

5. Sincronizar todo con el proyecto nativo

ionic build
npx cap sync android

Hay que repetir este paso cada vez que se instala un plugin nuevo — si no, Android Studio compila sin enterarse de que existe.

6. Conectar el repositorio del grupo

# ionic start ya corrió "git init" y el primer commit;
# solo falta apuntarlo al repo del grupo en GitHub
git remote add origin https://github.com/<usuario-lider>/grupo-2026.git
git branch -M main
git push -u origin main

# cada integrante trabaja en su propia rama
git checkout -b feature/alta-empleado

La consigna pide documentar la branch de cada tarea en el README — nombrar las ramas por funcionalidad (feature/alta-empleado, feature/qr-mesa) hace ese README mucho más fácil de mantener.

03

Angular, Ionic y Capacitor: quién hace qué

No son tres alternativas que compiten entre sí — son tres capas que se apilan, cada una responsable de una parte distinta del problema.

Angular lógica y estructura de la app

Es el framework de aplicación: componentes, servicios, routing, formularios, HttpClient/RxJS. Define qué pantallas existen, cómo navegan entre sí, cómo se guarda el estado (el carrito del pedido, el usuario logueado) y cómo se habla con Supabase. Todo lo que ya saben de Angular se aplica tal cual.

Ionic componentes de interfaz + CLI

No reemplaza los templates de Angular: se usa adentro de ellos. En vez de <button> y <div> sueltos, usan componentes ya pensados para mobile: <ion-header>, <ion-list>, <ion-modal>, <ion-fab>. La UI se sigue armando en Angular (HTML + SCSS); Ionic aporta el vocabulario visual (que además se adapta solo entre estilo iOS/Android) y su CLI (ionic serve, ionic build, ionic generate).

Capacitor el puente hacia lo nativo

Acá está el cambio real respecto a lo que ya hicieron. Capacitor toma el build web (el HTML/CSS/JS que compilan Angular + Ionic) y lo empaqueta dentro de una app Android de verdad, corriendo adentro de un WebView. Expone plugins (@capacitor/camera, @capacitor/geolocation, @capacitor/push-notifications) que son funciones de TypeScript que, por detrás, llaman código nativo Android. Ustedes llaman await Camera.getPhoto() desde un service de Angular como si fuera una promesa cualquiera.

El flujo de comandos, de código a app corriendo

Cada vez que tocan algo que Capacitor necesita ver (agregan un plugin nativo, cambian el ícono, etc.) hay que reconstruir y sincronizar. Para cambios de solo HTML/TS/SCSS alcanza con ionic serve en el navegador — pero ojo, ahí los plugins nativos (cámara, QR, vibración) no funcionan; para probarlos de verdad hace falta un dispositivo o emulador.

04

Para qué sirve Android Studio

No reemplaza a VS Code: es el panel de control de la capa nativa, la que vive en la carpeta /android que genera Capacitor. La mayoría del código del día a día se sigue escribiendo en VS Code, exactamente como ya vienen trabajando.

Se abre puntualmente para:

  • Correr la app en el emulador (AVD Manager) sin necesitar un celular a mano — útil para probar rápido entre los cuatro.
  • Ver Logcat: el log nativo en tiempo real. Cuando un plugin de Capacitor falla (cámara que no abre, permiso no concedido), el error casi nunca aparece en la consola del navegador — aparece acá.
  • Declarar permisos nativos en AndroidManifest.xml (cámara, ubicación, vibración, notificaciones). Muchos plugins los agregan solos al instalarlos, pero conviene saber dónde mirar cuando algo se niega en tiempo de ejecución.
  • Generar el APK/AAB firmado, necesario para instalar exactamente la misma versión en los cuatro celulares del grupo antes de cada entrega.
  • Ajustar recursos gráficos por densidad de pantalla: el ícono adaptativo y los splash screens estático/animado que pide la consigna se configuran acá si el generador automático de Capacitor no alcanza.
No hace falta saber Java/Kotlin

Casi todo lo que necesita este TFI (cámara, QR, geolocalización, notificaciones push, vibración, acelerómetro) ya existe como plugin oficial de Capacitor. Android Studio se usa como consola de control nativo — no como editor principal de código.

VS Code vs. Android Studio: quién hace qué

06

Un mismo componente, dos mundos

Lo que las secciones anteriores explican en teoría, acá en código: la misma tarjeta de plato del menú, primero en Angular puro (como la escribirían para cualquier web) y después adaptada con Ionic más un toque de Capacitor.

Versión A — Angular puro

Esto corre en cualquier navegador. No sabe que puede terminar dentro de un celular.

plato-card.component.ts

import { Component, Input } from '@angular/core';
import { CommonModule } from '@angular/common';

@Component({
  selector: 'app-plato-card',
  standalone: true,
  imports: [CommonModule],
  templateUrl: './plato-card.component.html',
  styleUrls: ['./plato-card.component.scss']
})
export class PlatoCardComponent {
  @Input() nombre = '';
  @Input() descripcion = '';
  @Input() precio = 0;
  @Input() imagenUrl = '';

  cantidad = 0;

  agregar() {
    this.cantidad++;
  }
}

plato-card.component.html

<div class="card">
  <img [src]="imagenUrl" [alt]="nombre" class="card-img" />
  <div class="card-body">
    <h3>{{ nombre }}</h3>
    <p>{{ descripcion }}</p>
    <div class="card-footer">
      <span class="precio">${{ precio }}</span>
      <button (click)="agregar()">Agregar ({{ cantidad }})</button>
    </div>
  </div>
</div>

plato-card.component.scss

Versión B — con Ionic, pensada para Android

Mismo componente, misma lógica. Cambia el vocabulario del template (etiquetas ion-* en vez de HTML plano) y aparece una sola línea que ya no es ni Angular ni Ionic: es Capacitor hablando directo con el motor de vibración del teléfono.

plato-card.component.ts

import { Component, Input } from '@angular/core';
import { CommonModule } from '@angular/common';
import {
  IonCard, IonCardHeader, IonCardTitle, IonCardContent,
  IonImg, IonButton, IonBadge, IonIcon
} from '@ionic/angular/standalone';
import { addIcons } from 'ionicons';
import { addOutline } from 'ionicons/icons';
import { Haptics, ImpactStyle } from '@capacitor/haptics';

@Component({
  selector: 'app-plato-card',
  standalone: true,
  imports: [CommonModule, IonCard, IonCardHeader, IonCardTitle, IonCardContent, IonImg, IonButton, IonBadge, IonIcon],
  templateUrl: './plato-card.component.html',
  styleUrls: ['./plato-card.component.scss']
})
export class PlatoCardComponent {
  @Input() nombre = '';
  @Input() descripcion = '';
  @Input() precio = 0;
  @Input() imagenUrl = '';

  cantidad = 0;

  constructor() {
    addIcons({ addOutline });
  }

  async agregar() {
    this.cantidad++;
    await Haptics.impact({ style: ImpactStyle.Light }); // vibración corta al tocar
  }
}

plato-card.component.html

<ion-card>
  <ion-img [src]="imagenUrl" [alt]="nombre"></ion-img>
  <ion-card-header>
    <ion-card-title>{{ nombre }}</ion-card-title>
  </ion-card-header>
  <ion-card-content>
    <p>{{ descripcion }}</p>
    <div class="footer">
      <ion-badge color="tertiary">${{ precio }}</ion-badge>
      <ion-button (click)="agregar()">
        <ion-icon slot="start" name="add-outline"></ion-icon>
        Agregar ({{ cantidad }})
      </ion-button>
    </div>
  </ion-card-content>
</ion-card>

plato-card.component.scss

.footer { display: flex; justify-content: space-between; align-items: center; margin-top: 8px; }

Qué cambió, en concreto

Parte del códigoAngular puroCon Ionic
Lógica (TypeScript)Prácticamente idéntica: sigue siendo un componente standalone con @Input y un método de click. Ionic no le agrega complejidad a la lógica.
Etiquetas del template<div>, <button> genéricos<ion-card>, <ion-button>: ya traen efecto ripple y feedback táctil, y se adaptan solas al estilo de Android
Colores/estilosHex hardcodeado (#2e63c9) repetido por componentecolor="tertiary" lee la paleta global de variables.scss: cambiás un color una vez y se actualiza en toda la app
Acceso al hardwareNo existe — un navegador no vibraUna línea de Capacitor (Haptics.impact()) que ni Angular ni Ionic saben hacer por su cuenta
La idea para quedarse

El componente sigue siendo Angular de punta a punta. Ionic solo le cambia el vocabulario visual al template. Capacitor es la única línea que de verdad toca el teléfono. Ese patrón — lógica en Angular, presentación en Ionic, hardware en Capacitor — se repite en las 31 funcionalidades del TFI.
